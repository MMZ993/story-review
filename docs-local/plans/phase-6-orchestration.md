# Phase 6 — Orchestration (FastAPI) plan

## Objective

Implement the FastAPI orchestration service from `docs/design/api-contract.md` and
`docs/design/data-flow.md` — all nine endpoints under `/api/v1`, flows 1–4, gate
precedence, turn leases, idempotency (stored canonical responses), durable Cloud SQL
records (locally the compose Postgres substitute), the direct MCP client wrapper
(timeouts/retries per `docs/design/observability.md`), and facilitator session
reconciliation.

Orchestration consumes the frozen Phase 5 invocation interface
(`docs-local/plans/phase-5-agents.md` appendix) against the compose `local-agents`
adapters; switching to Agent Engine later is configuration (Phase 8).

Per development-plan.md exit criteria: integration tests against the compose stack
(local adapters) cover flows 1–4, gate outcomes, park-at-10, the PO-acceptance path,
and idempotent retries.

Cost: Vertex AI tokens only (via the adapters the orchestration tests invoke). Cloud
SQL stays STOPPED throughout Phase 6 — all orchestration state (sessions, turns,
leases, idempotency keys, agent-run records) lives in the compose `postgres:16`
substitute, with the schema applied by the same migration mechanism that will run
against Cloud SQL (repository-layout.md "Local compose").

## Increment-0 owner decisions (settled 2026-09-13 — D15)

1. **Packaging**: `orchestration/` uv package (`orchestration` 0.1.0, FastAPI +
   uvicorn, requirements.lock pinning fastapi/uvicorn/asyncpg/mcp/google-cloud-storage
   as needed), root-context Dockerfile like the MCP services, wired into compose as a
   `local`-profile service in front of the existing stack. Per repository-layout.md —
   confirm.
2. **Persistence layer**: hand-written ordered SQL migrations in
   `deploy/cloud-sql/migrations/` + `run-migrations.sh` (repository-layout.md is
   prescriptive: ordered SQL files, no ORM framework named). Implementation via a thin
   asyncpg repository module enforcing the schemas.md database constraints (unique
   idempotency keys per route, turn unique per `(session_id, turn_number)`, one lease
   row per session, etc.) with conditional `UPDATE`s for claim/lease semantics — no
   ORM. Confirm (D15 candidate).
3. **Test strategy (extends D13)**: deterministic orchestration tests use **fake
   in-process agent clients** implementing the frozen adapter interface (scripted
   typed outputs / structured errors — no HTTP, no LLM) so gates, leases, idempotency,
   and reconciliation logic are testable without model cost; **flow integration tests
   run against the compose stack with the real adapters** (real Vertex calls, main PC
   only) as the increment live gates. Mocking is confined to orchestration's own
   downstream seam — LLM behavior itself is never scripted (D13 intact). Confirm.
4. **Idempotency-key storage and replay semantics**: per-route key + request
   fingerprint + stored canonical response (`CanonicalOperationResult` — never signed
   URLs; replay regenerates them). Keys scoped per endpoint + session per
   api-contract.md. Implemented as a DB claim row written with the lease acquisition
   (in-progress → completed with canonical response) so a crashed request leaves a
   recoverable in-progress state. Confirm.
5. **Signed URLs locally**: report downloads are generated by orchestration through
   the GCS storage library; in compose the URLs point at the fake-gcs endpoint the
   same way the artifact/report servers use it. Exact fake-gcs signed-URL mechanics
   (it supports `?signature`-style access on `signedUrl` emulation — to be verified
   empirically at increment 4; fallback: unsigned direct fake-gcs object URL with the
   same response shape, recorded as a local-only substitution decision). Settle
   empirically.
6. **Facilitator reconciliation locally**: the ambiguous-timeout recovery check
   (agents.md § Session and invocation semantics — inspect ADK session events tagged
   with the invocation ID before re-invoking) is implemented against the local
   adapter's Postgres session backend the same way it will run against Agent Engine.
   Confirm the invocation-ID tagging mechanism with the facilitator adapter's actual
   interface at increment 3; raise any divergence with the owner.

## Implementation increments

### 0. Packaging skeleton + persistence + idempotency/lease primitives (local)

- Settle the decisions above; record D15 (+ amendments) in local-decisions.md.
- uv package skeleton, strict env-driven config (service URLs, DB DSN, bucket,
  deadline/timeout constants per observability.md), health-check scaffolding.
- SQL migrations + `run-migrations.sh`; asyncpg repository: record CRUD + constraint
  enforcement + idempotency claim (in-progress/completed, body fingerprint) +
  turn-lease acquire/renew/release with TTL 6 min and token-holder checks.
- Test-first deterministic tests against compose Postgres (or a throwaway local
  Postgres in the test target) covering: key replay (same body → stored canonical
  response; different body → `IDEMPOTENCY_KEY_REUSED`), lease contention
  (`SESSION_LOCKED` + `retry_after_seconds`), expired-lease takeover, unique turn
  number.

### 1. MCP client wrapper + stories endpoints + health (local)

- Direct MCP client wrapper (streamable HTTP, mcp SDK as used by the contract suite):
  story `list_stories`/`get_story` proxy (optional case-insensitive title `filter`),
  artifact `save_artifact`/`get_artifact`/`list_artifacts`, report `render_report`;
  timeout/retry policy per observability.md (60 s short calls, 3 attempts, jittered
  backoff 1 s/2 s, retry only on connection/timeout/retryable 5xx; never 4xx,
  schema-validation, auth, idempotency mismatch), remaining-deadline clamping with
  response-cleanup reserve.
- `GET /api/v1/stories`, `GET /api/v1/stories/{story_id}` (404/503 mapping),
  `GET /health` with downstream reachability flags.
- Deterministic tests against the compose `local` stack (story MCP real, no LLM).

### 2. Flow 1 — session creation + browse/history read paths (local + live gate)

- `POST /api/v1/sessions`: idempotency claim → `get_story` → `story_run_id` creation →
  idempotent story-artifact save → parallel reviewer fan-out (asyncio.gather) →
  artifact saves + `AgentRunRecord`s → synthesis → save + record → facilitator
  opening turn (turn 1, `invoke` = none enforced) → `TurnRecord` + response
  persistence → `201 CreateSessionResponse`; 409 on existing active session for the
  story; 5-minute deadline.
- `GET /api/v1/sessions` (limit/cursor, `updated_at` desc), `GET /api/v1/sessions/{id}`
  (`SessionDetail` with server-side artifact fetching).
- Deterministic tests with fake agent clients (success, partial-failure recovery via
  key replay, active-session 409); **live gate (main PC)**: one real session creation
  over compose HTTP → schema-valid `CreateSessionResponse`.

### 3. Flow 2 — dialogue turns: lease, delegation execution, gate precedence (local + live gate)

- `POST /api/v1/sessions/{id}/turns`: lease acquisition → lineage-scoped input
  assembly (story + latest artifacts per perspective) → facilitator session-scoped
  invocation (session backend = the same compose Postgres) → `TurnRecord` on success →
  delegation execution per `DelegationDecision` (both/business/engineering fan-out
  with previous-review + `extra_context`; `reuse_previous` re-synthesis only;
  `invoke=none` dialogue only) → at-most-once synthesis per turn when new artifacts
  exist or `reuse_previous` → synthesis appended to session context → **gate
  precedence** (po_accepted → park-at-10 → continue-on-new-synthesis →
  open_issues-empty finalize) → single `TurnResponse` per request.
- `SESSION_READ_ONLY` 409 on parked/completed; `SESSION_LOCKED` 409; empty-message
  422; `DELEGATION_VALIDATION` 422 non-retryable.
- Facilitator ambiguous-timeout reconciliation (decision 6).
- Deterministic tests: gate truth table (scripted facilitator outputs), park at
  facilitator turn 10, lock serialization, retry with same key. **Live gate**: the
  example-interaction dialogue arc over compose HTTP (re-review turn, re-synthesis,
  continue), evidence in Runbook 12.

### 4. Flows 3+4 — finalization, reports, PO acceptance (local + live gate)

- Finalization core: deterministic `finalized-review` artifact (latest synthesis +
  dialogue resolutions from `ResolutionItem`s + PO acceptance state) → `render_report`
  per requested format (idempotent) → report references persisted → session
  `completed` invariants (schemas.md) → signed URLs (decision 5) → `TurnResponse`
  with `report` entries.
- `po_accepted=true` turn: bypasses facilitator/delegation, next chronological turn
  number, no `facilitator_turn_count` increment, synchronous finalize in the same
  response.
- `POST /api/v1/sessions/{id}/finalize` retry endpoint with the four-state behavior
  table (finalizing reacquire/completed replay-no-write/active 409 `NOT_FINALIZING`/
  parked 409 `SESSION_READ_ONLY`); render failure → 503, stays `finalizing`.
- `GET /api/v1/sessions/{id}/report` (completed only, fresh signed URLs,
  `REPORT_NOT_READY` 409).
- Deterministic tests: finalize state machine, po_accepted path, render-failure retry
  recovery, replay after lost response. **Live gate**: full session from creation to
  downloaded report over compose HTTP.

### 5. Exit gate — full integration suite over compose (main PC)

- `tests/integration/` orchestration suite against `agents-compose-up` stack: flows
  1–4 end-to-end, gate outcomes, park-at-10, PO-acceptance path, idempotent retries
  (same key replay after each mutating endpoint type), lease contention. All
  regression suites stay green.
- Independent read-only review of the phase diff; phase marked COMPLETE in
  development-plan.md; Runbook 12 completion-review section.

## Risks and controls

- **Gate-precedence complexity**: truth-table deterministic tests with scripted
  facilitator outputs before any live run (decision 3).
- **Idempotency/lease race windows**: constraint-enforced DB claims, crash-window
  tests (in-progress recovery) — same rigor as the artifact-server claim-before-write
  work (Runbook 10 §2).
- **fake-gcs signed URLs**: empirically verified at increment 4 with an explicit
  local-substitution fallback recorded if emulation is partial (decision 5).
- **Deadline correctness**: clamping unit tests (attempt-not-started-when-it-cannot-
  fit) per observability.md.
- **Adapter/AE divergence**: reconciliation path (decision 6) is exercised against the
  local adapter now and re-verified against Agent Engine in Phase 8.
